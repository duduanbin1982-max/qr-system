# 一次性发布门禁升级

## 适用范围

当前生产为 `787319edbdfa6ce2c17c23eeeb5e2fdeaa68598d`，普通发布入口正确拒绝
PR #111 对 `scripts/code_only_release.py` 的修改。本入口只安装已审核的新门禁，
不增加普通发布白名单。它不是通用的跳过预检开关。

唯一允许的门禁内容转换为 Git blob
`2451adc20d00fc4841638961111f8815b1eabadd` →
`f619adedac535e03735f98f40adaa049b6eb9c1b`，目标提交固定为
`8f928c2e6040346b986dac97d10fd50eb659140e`。其余四个发布控制文件和围栏运行时
必须不变。差异只能包含 `scripts/code_only_release.py` 与其已审核测试文件；
拒绝 bootstrap 自修改、业务代码、数据库、附件、前端、依赖变更、文件删除、
符号链接和模式变化。

## 信任与审核

先独立审核并合并本修复，记录完整 merge SHA 和 bootstrap 文件的 SHA256。
执行人从获准提交导出 bootstrap 到两个 worktree 以外的受控目录，并在启动 Python
之前用独立审核记录中的 SHA256 验证文件。不得直接执行目标门禁来授权自身；不得
编辑生产 worktree、使用 reset 或覆盖生产控制文件。用户 ID 1000/1004 是生产系统
操作人与批准人，不代表 GitHub 身份；命令行记录它们不代替真实批准。

bootstrap 只从当前生产提交读取发布脚本、备份、围栏、证据及回退控制，生成私有
临时副本。只替换三个已固定的源码位置：门禁控制转换检查、门禁路径例外、临时
发布器来源验证；以及将控制文件来源定位到该临时副本。替换点漂移时拒绝运行。
实际执行的验证器来自旧生产提交，不导入新门禁。每次预检重新检查完整目标 SHA、
根路径、变更路径、控制文件 Git 条目及生产控制文件实际字节。

完整后端测试也调用前端导入环门禁，需要 `@babel/parser`。bootstrap 从前后提交
均未改变的 package/lockfile 在私有临时目录运行 `npm ci --ignore-scripts`，仅将
测试依赖链接到发布器创建的临时测试 worktree；拒绝生产和目标 worktree。保留
全部后端测试，不修改生产依赖，不执行前端构建或静态资源发布。

## 执行顺序

1. 只读核实生产 HEAD、`.deployed_commit`、健康接口与获准基线一致。核对新提交
   是该基线的后代，单独目标 worktree 干净，新的维护窗口和停机上限仍有效。
2. 使用新 bootstrap 发布专用幂等键；旧 Task 7 幂等键不自动转用于新目标。
3. 导出、外部校验 bootstrap 后，以同一组完整参数执行 `--check-only`。
   该模式只生成临时文件、读取生产数据库副本并运行目标全量后端测试，不写入
   生产证据，不启动/停止服务，不建立围栏。
4. 预检和独立审核通过，取得本次单独部署授权后，用 `--execute` 替换
   `--check-only`。必须传入 `--project-root`、`--tool-root`、完整
   `--target-commit`、`--deployment-key`、`--approved-bootstrap-sha256`、
   `--operator-user-id 1000`、`--approver-user-id 1004`。
5. 首先以排他创建并 fsync 的方式保存 `<key>.bootstrap.json`，记录内容指纹、
   控制文件、前后版本和人员。然后进入旧生产发布器，重新预检、建立围栏、停止
   服务、生成并验证数据库/附件/前端备份、捕获受保护事实指纹。
6. 切换完整合并提交，在围栏内验收目标版本、V096、业务事实和受保护文件，
   持久化成功证据后才解除围栏。保留全部备份、日志和证据。

## 失败与恢复

普通发布流程仍禁止发布控制自行修改；本次升级后这个限制继续有效。bootstrap
只适用于上述唯一基线和门禁 blob 对，不能用于下一次门禁升级。

切换前失败走旧发布器的受控中止；切换后失败仍使用临时副本中旧的回退控制，
恢复旧提交和版本标记。数据库、附件、前端只验证，不自动用备份覆盖生产事实。
验收失败时保留围栏、停止服务、保留证据。证据文件部分写入也阻止复用幂等键；
需核对状态后提供新键，不删除失败证据。

目标合并提交固定为 `8f928c2e6040346b986dac97d10fd50eb659140e`，成为实际发布目标。
bootstrap 工具本身从独立合并后的文件导出并校验 SHA-256；它不会要求目标提交
修改自身，也不会允许任意后续提交复用本次授权。升级成功即包含 Task 5 门禁，
不再将生产倒退到其祖先提交。

## 本地验收

执行 `python -m pytest -q tests/test_release_gate_bootstrap.py
tests/test_code_only_deployment.py tests/test_deployment_contracts.py
tests/test_operations_script_boundary.py`，
再运行全量后端测试与 `npm run check:architecture`。隔离 Git worktree 验证原门禁
拒绝、bootstrap 通过、未授权内容/符号链接/源码漂移拒绝；确认既有围栏、备份、
回退、健康及证据持久化契约继续通过。最终生产预检以真实目标 merge SHA 重跑。
Linux 还会执行真实旧发布器的成功和健康失败回退演练，仅替换服务、HTTP 和测试
运行器进程边界；验证数据库字节、附件、前端文件、版本标记、终态证据和围栏。
