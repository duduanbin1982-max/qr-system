# 生产排程 UI/UX 修复阶段

## 阶段边界

本阶段只改生产排程前端交互和展示，不改变排程算法、排程版本状态、报工事实或生产环境数据。代码位于 `codex/scheduling-ui-ux-repair`，生产主机 `192.168.1.8` 未连接、未部署。

## 已完成

1. 订单详情右侧抽屉：Teleport 到 `body`，覆盖概览、工序进度、路线/工序版本、标准工时来源、节点、计划/实际时间、风险、阻断原因和版本审计；支持 Esc 关闭、重试和固定底部操作区。
2. 三栏节点排队看板：左侧工序、中间同类生产节点、右侧当前节点时间轴；任务点击进入订单详情，同类节点仍可互换，移动端降级为单列。
3. 阻断任务中心：统一显示订单、工序、阻断原因，并提供订单详情、节点查看、重新试排入口。
4. 订单筛选和保存筛选：订单号、产品编码/名称、优先级、状态、交期范围、风险、锁定状态；命名方案保存在浏览器本地，可加载、清空和删除。
5. 甘特图 CSV 与计划/实际对比：订单和工序节点均可导出当前筛选结果；甘特条以计划条和实际报工条并列展示，表格和订单详情显示实际开始/结束时间。
6. 普通排程弹窗统一为视口固定工作台/抽屉：订单编辑、节点调整和排程版本差异均不再定位在列表中部；窄屏占满视口并保持内容独立滚动。

## 验证结果

- 全量单元测试：44 个测试文件，297 个测试通过。
- 新增 UI/UX 回归测试：订单抽屉生命周期、三栏节点看板、筛选方案持久化。
- 前端构建、API facade 检查、导入环检查通过。
- Playwright 端到端测试：20/20 通过；现有移动端和生产节点工作台响应式验收通过。

## 后续受控步骤

1. 代码审查并确认筛选字段与业务订单字段映射。
2. 在独立维护窗口部署到测试/验收环境，验证真实订单详情、节点排队、阻断原因和计划/实际数据。
3. 获得单独授权后再 commit、push、创建 PR；PR 合并后重新生成生产部署参数。
4. 生产部署前执行前端备份、健康检查和回退演练；本阶段不执行数据库迁移和生产数据写入。
