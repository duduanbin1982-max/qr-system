# 生产节点管理工作台 UI/UX 优化设计

日期：2026-09-20  
状态：设计已获业务确认，待用户复核规格文档后进入实施计划  
适用模块：生产管理 > 生产排程 > 生产节点管理

## 1. 背景

当前生产节点管理使用嵌入 GanttChart.vue 的普通弹窗，同时展示节点创建、节点列表、日历例外和能力限制。弹窗依赖全局 modal 样式，最大高度为 85vh，整个弹窗自身滚动。

现状存在以下问题：

1. 弹窗会受到排程页面当前滚动位置、父级布局和横向滚动容器影响，视觉上像是出现在列表中部。
2. 表单、节点列表、日历例外和能力限制纵向堆叠，无法在一个视口内完整显示。
3. 滚动后标题、当前节点和关闭/保存按钮离开视口，用户容易迷失操作上下文。
4. 能力限制字段较多，现有 900px 弹窗在常用分辨率下空间不足。
5. 节点管理界面继续堆积在 GanttChart.vue 中，会提高后续维护成本。

## 2. 目标与非目标

### 2.1 目标

- 弹窗始终相对浏览器视口定位，不受甘特图滚动位置影响。
- 在 1366×768 等常用分辨率下始终显示标题、页签和底部操作栏。
- 将节点列表、节点编辑、工作日历和能力限制分区，降低单屏信息复杂度。
- 支持大量节点搜索、按工序分组和快速切换。
- 桌面端和小屏端均能访问全部字段与操作。
- 防止切换节点、切换页签或关闭时丢失未保存内容。
- 保持现有权限、API、幂等键和审计语义不变。
- 从 GanttChart.vue 中拆出生产节点管理界面，形成独立可测试组件。

### 2.2 非目标

- 不修改生产节点数据库结构。
- 不新增或改变后端 API。
- 不改变自动排程、动态重排和节点容量算法。
- 不修改停机管理区域及排程调整弹窗。
- 不在本阶段重新设计全系统通用模态框。

## 3. 方案选择

采用“视口内全屏工作台式弹窗”，不采用普通加宽弹窗或右侧抽屉。

选择原因：

- 当前功能已包含四个相对独立的管理场景，不再是简单表单。
- 工作台能同时提供节点导航和当前节点编辑上下文。
- 能力限制需要较大横向空间，右侧抽屉不适合。
- 固定外壳、局部滚动和分区保存能彻底解决信息显示不全问题。

## 4. 总体布局

工作台通过 Vue Teleport 挂载到 body，使用固定定位覆盖视口。

### 4.1 桌面端

- 适用宽度：不小于 900px。
- 外层距离视口四周 16–24px。
- 最大宽度约 1400px，宽度不低于视口的 92%。
- 高度使用 calc(100dvh - 32px)。
- 工作台由固定标题栏、固定页签栏、可滚动内容区和固定底部操作栏组成。
- 内容区采用双栏：
  - 左侧约 260–300px：节点搜索、状态筛选、按工序分组的节点列表。
  - 右侧：当前节点摘要及当前页签内容。
- 左侧节点列表和右侧内容区分别滚动，工作台外壳不滚动。

### 4.2 小屏端

- 适用宽度：小于 900px。
- 工作台占满整个视口，不保留外边距和圆角。
- 左侧节点列表折叠为顶部节点选择器。
- 页签允许横向滚动。
- 表单改为单列。
- 能力限制行改为卡片或分组字段，不要求页面横向滚动。
- 底部取消和保存按钮保持固定。

## 5. 页签职责

### 5.1 节点列表

- 默认打开的页签。
- 支持按节点编码、节点名称搜索。
- 支持全部、启用、维护中和停用状态筛选。
- 按工序分组显示节点数量。
- 节点项显示编码、名称、状态和容量模式。
- 选择节点后，右侧显示基本摘要、日容量、能力限制数量和未来日历例外数量。
- “新建生产节点”进入节点编辑页签并使用空表单。
- “编辑”进入节点编辑页签并加载选中节点。

### 5.2 节点编辑

- 新建时可以选择所属工序。
- 编辑已有节点时所属工序保持只读。
- 维护节点编码、节点名称、容量模式、工作日历、状态、变更原因和幂等键。
- 保存成功后刷新节点列表，保持当前节点选中，并回到节点摘要。
- 保存失败时保留全部输入。

### 5.3 工作日历

- 显示当前节点采用的基础日历和每日有效分钟。
- 按时间倒序显示维护、加班、停工假日和不可用例外。
- 新增例外使用独立表单。
- 保存成功后只刷新当前节点的日历数据。
- 日历加载失败不影响节点基本资料和能力限制。

### 5.4 能力限制

- 显示当前节点的产品、产品族、材料、规格、路线版本和工序版本限制。
- 一行或一卡片代表一条限制。
- 容量模式为 batch 时才显示最大批量、批次分钟、换型分钟和允许混单。
- 空限制列表继续表示仅按所属工序匹配。
- 保存时保留现有原因、幂等键和整组替换语义。

## 6. 交互规则

1. 四个页签共享同一个当前节点。
2. 切换页签不清除节点选择。
3. 每个页签独立保存，不提供含义不明确的“全部保存”。
4. 点击遮罩不关闭工作台。
5. 点击关闭、按 Esc、切换节点或切换页签时，如果当前表单已修改，显示“放弃更改 / 继续编辑”确认。
6. 保存期间禁用重复提交。
7. 保存完成后仅刷新受影响的数据，不关闭工作台。
8. 工作台关闭后刷新甘特图使用的节点名称、状态和容量摘要。
9. 工作台打开期间锁定背景页面滚动。

## 7. 组件与职责

新增目录：

    frontend/src/components/production-nodes/
    ├── ProductionNodeWorkbench.vue
    ├── NodeListPanel.vue
    ├── NodeEditorPanel.vue
    ├── NodeCalendarPanel.vue
    └── NodeCapabilityPanel.vue

### 7.1 ProductionNodeWorkbench.vue

负责：

- Teleport、遮罩和工作台外壳；
- 页签状态；
- 当前节点；
- 未保存状态协调；
- 关闭确认；
- 键盘和焦点管理；
- 桌面端/小屏端布局切换。

它不直接实现生产节点业务规则，也不直接复制 API 请求逻辑。

### 7.2 各面板组件

- NodeListPanel.vue：搜索、筛选、分组和节点选择。
- NodeEditorPanel.vue：节点创建与修改表单。
- NodeCalendarPanel.vue：基础日历摘要、例外列表与新增例外。
- NodeCapabilityPanel.vue：能力限制列表、批处理字段和保存。

每个面板只处理自身界面状态，通过明确事件调用管理器动作。

### 7.3 状态管理

现有 useProductionNodes.js 继续作为生产节点数据和命令的唯一来源，负责：

- 加载节点和工作日历；
- 创建、更新节点；
- 加载和保存能力限制；
- 创建日历例外；
- 权限检查；
- 后端错误提示。

实现时增加一个小型工作台适配层，将现有 ref、computed 和命令按 state、permissions、actions 分组传给工作台，避免组件再次实例化 useProductionNodes()，也避免同一节点数据出现两份状态。

GanttChart.vue 只保留：

- 打开工作台的按钮；
- ProductionNodeWorkbench 组件调用；
- 关闭后刷新排程相关节点摘要的入口。

## 8. 数据流

    打开工作台
      → 加载节点与基础日历
      → 默认进入节点列表
      → 选择当前节点
      → 按需进入编辑 / 日历 / 能力页签
      → 页签按需加载详细数据
      → 独立保存当前页签
      → 刷新当前节点及相关摘要
      → 保持工作台和节点选择

能力限制和日历例外采用延迟加载，避免打开工作台时请求全部节点的详细数据。

## 9. 错误处理

- 节点列表加载失败：列表区域显示错误和“重新加载”。
- 日历或能力加载失败：只在对应页签显示错误，不清空其他页签。
- 保存失败：保留表单值，显示后端返回的具体错误。
- 权限不足：隐藏或禁用对应页签的编辑操作，但允许具备查看权限的用户查看摘要。
- 幂等或行版本冲突：提示刷新当前节点后重试。
- 工作台内部发生异常时，不影响甘特图主页面。
- 异步请求完成前切换节点时，旧请求结果不得覆盖新节点状态。

## 10. 可访问性

- 工作台使用 role=dialog 和 aria-modal=true。
- 标题与工作台建立 aria-labelledby 关联。
- 打开后聚焦标题或第一个可操作元素。
- Tab 和 Shift+Tab 焦点保持在工作台内部。
- 按 Esc 执行关闭流程，并遵守未保存确认。
- 关闭后焦点返回“生产节点管理”按钮。
- 页签使用标准 tab 语义和方向键切换。
- 加载、成功和失败状态提供可读文本，不只依赖颜色。

## 11. 测试设计

### 11.1 单元与组件测试

- 默认进入节点列表页签。
- 选择节点后四个页签共享节点 ID。
- 新建和编辑正确初始化表单。
- 历史输入在保存失败后保留。
- 点击遮罩不关闭。
- 未保存状态阻断切换节点、切换页签和关闭。
- 保存成功只刷新当前页签。
- 批处理字段只在 batch 模式显示。
- 权限控制正确隐藏或禁用操作。
- 异步旧请求不会覆盖新节点。

### 11.2 浏览器测试

- 页面滚动到顶部、中部和底部时，工作台位置均相对视口固定。
- 1366×768 下标题、页签和底部操作栏始终可见。
- 节点数量超过 23 条时可以搜索并选择。
- 多行能力限制时所有字段和保存按钮可访问。
- 小于 900px 时切换为全屏单列布局。
- Esc、焦点锁定和关闭后焦点返回正常。

### 11.3 回归验证

- 生产节点的新增、修改、能力保存和日历例外 API 请求结构不变。
- 甘特图、自动排程、动态重排和停机管理不受影响。
- 前端 API facade、导入循环检查、单元测试、浏览器测试和生产构建通过。

## 12. 最终验收标准

1. 工作台永远相对浏览器视口定位，不出现在甘特图列表中部。
2. 常用桌面分辨率下标题、页签和底部操作栏始终可见。
3. 所有信息都能通过局部滚动访问。
4. 节点、日历和能力配置不再纵向堆叠在同一个长页面。
5. 小屏端可以完成节点选择、编辑、日历和能力维护。
6. 未保存内容不会因误触遮罩、切换节点或切换页签而丢失。
7. 保持现有权限、API、幂等和审计行为。
8. 不需要数据库迁移或后端部署变更。

## 13. 发布与回退

本改造仅涉及前端代码：

- 发布时构建并原子替换 public/static。
- 不执行数据库迁移和附件迁移。
- 部署后验收桌面端和小屏端布局、生产节点的四类操作及甘特图回归。
- 失败时恢复部署前前端发布包并回退代码提交，数据库和附件保持不变。
