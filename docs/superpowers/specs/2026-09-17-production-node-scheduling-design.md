# 生产节点排程改造设计

日期：2026-09-17  
状态：设计已获业务确认，待规格文档复核后进入实施计划  
适用系统：生产管理系统排程、节点容量、停机、动态重排、甘特图和相关报表

## 1. 背景与目标

当前系统的容量排程已经使用 `process_production_lines` 中的独立资源记录，但字段、接口、停机记录和用户界面仍沿用“产线”概念，同时保留旧的订单级 `production_lines` 模型。这会造成资源语义混乱：实际排程需要的是“一个可独立占用的物理生产能力单元”，而不是订单级产线。

本改造的目标是建立规范的“生产节点”模型，使每个节点具有独立的能力、日历、停机、占用和历史记录，并让新排程以节点为唯一资源。旧产线结构仅用于历史追溯和过渡兼容，不能继续成为新排程的资源依据。

本设计不改变已完成生产事实、历史工资事实、既有工时标准或已发布排程的历史语义。

## 2. 已确认的业务定义

### 2.1 生产节点

生产节点定义为一个稳定、可独立占用的物理生产能力单元，例如一台设备、一个工位或一个固定作业小组。员工不是生产节点，员工只被安排到节点执行任务。

### 2.2 节点数量基线

首轮核心工序节点数量保持现有业务基线：

| 工序 | 节点数量 |
|---|---:|
| 下料 | 1 |
| 铆接 | 4 |
| 焊接 | 10 |
| 抛丸 | 1 |
| 打磨 | 1 |
| 镗孔 | 2 |
| 喷漆 | 2 |

### 2.3 节点互换和能力限制

同一工序下的节点默认可以相互替代，但每个节点允许配置能力限制。能力限制至少支持产品或产品族、材料、规格尺寸、路线版本和工序版本。自动排程只能从满足能力限制的节点中选择资源。

### 2.4 容量模式

节点支持两种模式：

- `exclusive`：独占模式，同一时间段只能执行一个任务，作为默认模式。
- `batch`：批处理模式，按批次上限、批次固定时间、换型时间和混批规则计算容量。

抛丸、喷漆等工序不得仅依据工序名称自动改为批处理；只有经过配置和审批后才可使用 `batch`。

### 2.5 任务拆分

- 普通数量订单可以按工件数量拆分到多个兼容节点并行加工。
- 单个序列工件的一道工序只能绑定一个节点，不允许跨节点拆分。
- 批处理节点按完整批次分配，并严格执行批量、混批和换型约束。

## 3. 总体架构

建立新的规范实体 `production_nodes`，并围绕它组织能力、日历、占用、停机和排程事实：

```text
工序
 └── 多个生产节点
      ├── 能力限制
      ├── 工作日历
      ├── 停机记录
      ├── 当前占用
      └── 历史排程事实

订单
 └── 订单工序
      └── 生产节点排程
```

新排程、冲突检测、容量计算、动态重排和甘特图均以 `production_node_id` 为资源主键。

旧 `production_lines` 是订单级历史模型，不再参与容量排程。旧 `process_production_lines` 作为迁移来源和过渡兼容来源，逐步映射到 `production_nodes`。

## 4. 数据模型

### 4.1 `production_nodes`

建议字段：

| 字段 | 作用 |
|---|---|
| `id` | 稳定节点 ID |
| `process_id` | 所属工序 |
| `node_code` | 节点编码，如 `WELD-01` |
| `node_name` | 节点名称 |
| `capacity_mode` | `exclusive` 或 `batch` |
| `status` | `active`、`inactive`、`maintenance` |
| `calendar_id` | 默认工作日历 |
| `legacy_process_line_id` | 原工序产线记录映射 |
| `created_at`、`updated_at` | 审计时间 |

节点编码在有效范围内唯一。节点停用代替删除；已被排程、报工或停机事实引用的节点不得删除。

### 4.2 `production_node_capabilities`

用于记录节点能力边界，至少支持：

- 产品或产品族；
- 材料、规格、尺寸；
- 路线版本；
- 工序版本；
- 是否允许批处理；
- 批次最大数量；
- 单批固定时间；
- 换型时间；
- 是否允许混合订单。

能力记录应具有状态和审计信息。新能力生效后不改写已发布排程的能力快照。

### 4.3 `production_node_calendar_overrides`

用于记录节点独立覆盖：

- 临时停机；
- 维护；
- 加班；
- 节假日；
- 特殊不可用时段。

无节点覆盖时继承工序默认日历；有覆盖时以节点日历为准。默认有效生产时间为每日 540 分钟，即 `08:00–12:00`、`13:00–18:00`。

### 4.4 排程事实字段

`order_process_schedules`、排程分段表、排程修订表和相关停机/占用事实增加或规范化以下字段：

- `production_node_id`；
- `node_code_snapshot`；
- `node_name_snapshot`；
- `capacity_mode_snapshot`；
- `calendar_snapshot`；
- `capability_snapshot`；
- `locked`；
- `lock_reason`；
- `assigned_quantity`；
- `occupied_minutes`。

`process_line_id` 在过渡期只读保留，并由节点映射产生；新排程不得要求调用方提供它。

## 5. 不可变约束

1. 节点 ID 永久稳定，节点改名不改变 ID。
2. 已有排程、报工或停机事实引用的节点只能停用，不能删除。
3. 已发布排程保存节点、能力、日历和容量快照，后续配置变化不改写历史结果。
4. 已锁定任务不能被自动重排。
5. 单序列工件的一道工序只能绑定一个节点。
6. 普通订单数量可拆分到多个兼容节点，拆分总量必须守恒。
7. `exclusive` 节点同一时段只能有一个任务。
8. `batch` 节点必须校验批量上限、批次时间、换型和混批规则。
9. 旧 `production_lines` 和旧 `process_line_id` 不接受新排程写入。
10. 节点新增、修改、停用、能力变更、日历变更、停机、改派、锁定、解锁、重排、提交、审批和发布均写入不可变审计事件。

## 6. 排程计算与动态重排

### 6.1 输入

排程输入包括订单优先级、交期、数量和序列号；订单绑定的路线/工序版本；精确标准工时及来源快照；工序依赖；兼容节点；节点能力、日历、停机和已占用时段；节点容量模式。

### 6.2 计算顺序

```text
订单排序
  → 展开路线工序
  → 校验订单/路线/工序版本和工时
  → 筛选兼容节点
  → 计算节点最早可用时间
  → 按节点容量分配数量
  → 处理跨班次和跨天
  → 校验工序前后依赖
  → 生成排程版本
  → 输出冲突和交期风险
```

所有时间以分钟计算。任务自动跳过休息、节假日、节点停机和不可用覆盖时段。前置工序未完成时，后置工序不得提前占用节点。

候选节点排序规则：最早完工、交期风险最低、当前负载最小、节点 ID 最小作为稳定兜底。

### 6.3 动态重排

订单优先级、数量或交期变化，或者发生停机、返工、实际报工和节点占用变化时：

- 已完成事实不改变；
- 已开始但未完成的任务只重排剩余数量；
- 已锁定任务不自动移动；
- 未锁定任务重新筛选节点并计算时间；
- 受停机影响的任务进入风险队列；
- 系统生成新的排程修订版，不覆盖旧版本；
- 变更原因、操作人、前后差异和计算快照写入审计记录。

## 7. 错误处理与事务边界

下列情况必须将订单工序置为 `blocked`，不得伪造为已排程：无可用节点、能力不匹配、缺少有效工时、版本绑定不一致、日历无可用时间、前置工序未就绪、锁定任务冲突、序列件拆分违规、批处理约束不满足。

统一返回结构化错误码：

- `NO_COMPATIBLE_NODE`
- `MISSING_WORK_TIME_STANDARD`
- `VERSION_BINDING_MISMATCH`
- `NODE_CALENDAR_UNAVAILABLE`
- `LOCKED_TASK_CONFLICT`
- `SERIAL_ITEM_SPLIT_FORBIDDEN`
- `BATCH_CAPACITY_EXCEEDED`

自动排程运行使用独立幂等键和排程运行台账。节点分配、时间分段、数量拆分和排程修订在同一事务中完成；任一关键写入失败则整次回滚。发布前再次检查节点占用、停机和锁定事实。重复幂等键只能返回原结果，不能重复占用节点。

## 8. 权限、UI/UX 和审计

### 8.1 权限

新增并拆分：

- `production_nodes:view`
- `production_nodes:manage`
- `production_nodes:capability_manage`
- `production_nodes:calendar_manage`
- `production_nodes:downtime_manage`
- `schedules:generate`
- `schedules:adjust`
- `schedules:lock`
- `schedules:unlock`
- `schedules:submit`
- `schedules:approve`

排程制单人和发布批准人必须不同。紧急解锁必须填写原因并保留操作前后快照。

### 8.2 节点管理界面

原“产线管理”改为“生产节点管理”，按工序分组显示节点、状态、容量模式、今日负载和停机状态。节点详情分为基本资料、能力限制、工作日历、停机维护、当前任务、历史占用和变更审计。旧产线 ID 只在审计管理员界面显示。

### 8.3 甘特图

纵轴采用“工序—生产节点”层级，例如焊接下展开焊接-01 至焊接-10。任务条显示订单、产品、工序、分配数量、时间、占用分钟、优先级、交期风险、容量模式和锁定状态。停机与非工作时间显示为不可占用区间。拖拽前实时校验能力、依赖、日历和冲突。

### 8.4 员工与节点分离

节点排程以物理容量为准。员工资质、当班和被安排到节点的关系单独建模；人员不足只产生“人力不足”风险，不伪造节点容量。

## 9. 分阶段迁移和发布

### V086：建立节点主数据

新增 `production_nodes`、能力、日历覆盖和节点审计表。现有 21 个 `process_production_lines` 资源一对一迁移为节点，保留 ID 映射和历史事实。默认全部为 `exclusive`。

### V087：增加节点排程事实

为排程、分段、停机和修订记录增加节点引用和快照字段。历史记录通过稳定映射补充节点引用；无法唯一映射的记录进入差异清单并阻断自动迁移。

### 双读兼容审计

新增开关：

```text
PRODUCTION_NODE_QUERY_ENABLED=false
PRODUCTION_NODE_COMPAT_AUDIT_ENABLED=false
PRODUCTION_NODE_WRITE_ENABLED=false
PRODUCTION_NODE_ENGINE_ENABLED=false
LEGACY_PROCESS_LINE_WRITE_BLOCKED=false
```

首轮只开启查询和兼容审计。新旧读取比较节点归属、占用分钟、时间段、停机、冲突、订单工序和甘特图结果；差异必须留证。

### 影子排程

对真实待排订单同时运行旧逻辑和节点逻辑，不发布、不影响生产。验证工时覆盖、负载、时间、风险、数量守恒、序列件单节点、停机和锁定约束。

### 节点写入切换

影子验收通过后，单独授权开启：

```text
PRODUCTION_NODE_WRITE_ENABLED=true
PRODUCTION_NODE_ENGINE_ENABLED=true
```

新排程正式写入节点事实，并生成只读兼容字段。已发布排程保持原版本，新排程或受控重排生成节点版本。

### 阻断旧写路径

双读差异持续为零、新排程无旧资源依赖、甘特图/停机/动态重排/报表完成切换、历史记录无未映射项且回退演练通过后，单独授权开启：

```text
LEGACY_PROCESS_LINE_WRITE_BLOCKED=true
```

旧表、旧字段和兼容查询继续保留用于历史追溯。

## 10. 测试矩阵

### 单元测试

覆盖节点能力匹配、独占冲突、批处理容量、批次/换型/混批、540 分钟日历、跨休息和跨天、数量拆分、序列件禁止拆分、停机排除、锁定不可移动、工序依赖、优先级和交期排序、动态重排剩余数量、幂等重放和并发冲突。

### 数据库和迁移测试

验证 21 个资源一对一映射、节点编码唯一、历史排程/分段/停机可映射、已完成事实不变、无孤立节点引用、外键错误为零、完整性检查为 `ok`、迁移可重复执行、迁移失败可恢复、旧结构未删除。

### API 和服务测试

覆盖节点查询与维护、能力/日历/停机、自动试排、人工调整、锁定/解锁、提交/审批/发布/取代、节点甘特图、负载看板、Legacy 查询、旧写阻断、越权访问和不可变审计。

### 前端测试

验证正常业务页面只显示“生产节点”；按工序折叠展示；节点状态、能力、负载、停机清晰；非法拖拽不能保存；阻断原因可定位；拆分结果可展开；锁定任务有明显标识；旧映射只在审计页面显示。

### 真实订单影子验收

使用真实待排订单验证 21 个节点加载、540 分钟容量、数量守恒、序列件单节点、独占无重叠、批处理约束、工序依赖、停机排除、锁定不移动、优先订单提前、风险可解释、外协/非排程不占内部节点、缺工时或缺节点明确阻断、幂等重放不重复占用。

## 11. 最终切换门槛

只有同时满足以下条件，才允许正式切换节点引擎：

1. 全量后端、前端和端到端测试通过；
2. 21 个核心节点全部完成映射；
3. 历史事实映射差异为零；
4. 双读兼容审计最新差异为零；
5. 真实订单影子排程无节点冲突；
6. 数量守恒率为 100%；
7. 序列件违规拆分为零；
8. 已完成历史事实变更为零；
9. 数据库完整性和外键检查通过；
10. 备份恢复和代码回退演练通过；
11. 版本化写入及旧写阻断仍由独立生产授权控制。

任一门槛不满足时，只保留节点查询和兼容审计，不开启正式节点写入。

## 12. 明确不在本设计范围

- 不修改已完成报工和工资事实；
- 不重新计算已发布历史排程；
- 不在首轮自动推断批处理能力；
- 不把员工直接建模为生产节点；
- 不删除旧表、旧字段、旧审计记录或历史备份；
- 不在本设计阶段执行生产迁移、停服、重启或开启生产写入。
