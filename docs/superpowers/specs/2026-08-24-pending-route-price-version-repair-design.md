# 待发布路线精确工价版本修复设计

日期：2026-08-24  
状态：设计章节已确认，待文档复核和详细实施计划

## 1. 背景与问题

当前“工资核算 - 工价版本”页面只从路线根的
`current_effective_version_id` 读取已发布路线，并要求路线版本和工序版本均为
`published`。因此，新建但尚未发布的路线版本不会进入工价引用目录。

与此同时，版本化工价服务已经要求新工价精确绑定：

```text
route_id
route_version_id
process_id
process_version_id
```

现有前端却只提交 `route_id + process_id`。这导致页面既无法选择待发布路线，
也没有完整履行后端的精确版本契约。

系统已经具备工序、路线和工价成组发布能力。正确修复方向不是放宽未发布
工价的批准条件，而是让被冻结的待审批路线可以建立工价草稿，并与路线及
其依赖工序在同一个事务中发布。

## 2. 已确认的业务决策

1. 路线处于 `draft` 时只显示工价覆盖预览，不能创建正式工价草稿。
2. 路线提交审批并进入 `pending_approval` 后，节点被冻结，才能针对精确路线
   版本和工序版本建立工价草稿。
3. 待发布路线的工价草稿不能单独批准，只能通过成组发布一起批准。
4. 路线版本被驳回到 `draft` 时，保留工价记录作为审计证据，但在同一事务中
   将关联工价草稿标记为 `voided`。
5. 已作废工价禁止批准、恢复或加入可提交的发布批次。路线重新提交后必须
   重新建立工价草稿。
6. 采用双入口联动：工价版本页面提供完整制单入口，路线详情提供带上下文的
   “为该版本定价”入口；两个入口共用同一精确定价表单和后端服务。
7. 不修改历史订单、已发布路线、已批准工价、工资事实或版本化工资台账。
8. 新路线版本不自动继承旧路线工价；旧工价只能作为只读参考。

## 3. 目标与非目标

### 3.1 目标

- 能够为 `pending_approval` 路线的每个精确工序版本建立工价草稿。
- 从选择、保存、审批到工资解析始终使用精确版本 ID。
- 保持工价制单、路线审批和发布批准的职责分离。
- 保证工序、路线和工价成组发布的事务原子性。
- 对驳回、并发、重复请求和内容变化提供稳定、可审计的处理。
- 兼容仍只需要当前已发布路线的旧引用客户端。

### 3.2 非目标

- 不允许草稿路线提前建立正式工价。
- 不允许待发布路线工价绕过成组发布单独批准。
- 不自动复制、继承或按相似度推断旧工价。
- 不在路线审批页面内嵌完整工资管理模块。
- 不重算历史工资，不改变历史订单或历史事实的版本绑定。

## 4. 总体架构

修复分为三个边界清晰的组件。

### 4.1 版本引用目录

引用目录负责回答“当前操作者可以对哪些精确路线节点定价”，不负责创建或
批准工价。目录返回：

```text
reference_key = <route_version_id>:<process_version_id>
route_id
route_version_id
route_version
route_name
route_category
route_version_status
route_content_digest
process_id
process_version_id
process_version
process_name
process_version_status
process_content_digest
seq_order
pricing_mode
can_create_price
requires_group_release
blocking_reason
```

`reference_key` 是前端选择、列表分组和测试断言的唯一键。不得再以
`route_id:process_id` 合并不同修订版。

目录包含两类可定价记录：

- 当前已发布路线：`pricing_mode=published_adjustment`；
- 待审批路线：`pricing_mode=pending_group_release`。

草稿路线不进入正式定价目录。路线详情通过版本上下文单独生成只读覆盖预览。

### 4.2 精确工价服务

精确工价服务负责创建、查询、批准和作废工价版本。它必须独立校验：

- 路线版本属于指定路线根；
- 工序版本属于指定工序根；
- 工序版本是指定路线版本中的节点；
- 路线版本为 `published` 或 `pending_approval`；
- 节点工序版本为 `published` 或 `pending_approval`；
- 内容摘要和创建时快照一致；
- 同一待发布路线节点不存在另一个可用工价草稿。

前端禁用状态只用于改善操作体验，不能代替服务和数据库约束。

### 4.3 成组发布服务

成组发布服务验证完整依赖，在同一个数据库事务中按以下顺序执行：

1. 发布批次包含的待审批工序版本；
2. 发布路线版本并切换路线根的当前版本指针；
3. 批准与路线节点精确匹配的工价草稿；
4. 写入版本、工价和发布批次事件。

任一步骤失败时，工序状态、路线状态、当前版本指针、工价状态和事件全部回滚。

## 5. 冻结与依赖规则

路线从 `draft` 提交到 `pending_approval` 时，服务必须验证每个节点引用的工序
版本状态只能是：

```text
published
pending_approval
```

仍为 `draft` 的工序版本可继续编辑，不能进入已冻结的待审批路线。路线引用
`pending_approval` 工序时，该工序、路线和对应工价必须进入同一个发布批次。

已被待审批路线引用的待审批工序版本不能单独驳回。必须先驳回依赖路线，使
路线回到草稿并作废相关工价，再处理工序版本。这样可避免工序内容改变而版本
ID 未变时复用旧工价。

## 6. 数据模型

新增 V074 数据库迁移，扩展 `route_price_versions`：

```text
status CHECK(status IN ('draft','approved','retired','voided'))
idempotency_key TEXT NULL
request_digest TEXT NOT NULL DEFAULT ''
route_content_digest_snapshot TEXT NOT NULL DEFAULT ''
process_content_digest_snapshot TEXT NOT NULL DEFAULT ''
voided_at TEXT NULL
voided_by INTEGER NULL
voided_by_name TEXT NOT NULL DEFAULT ''
void_reason TEXT NOT NULL DEFAULT ''
```

对非空 `idempotency_key` 建立唯一索引。迁移必须安全重建 SQLite 状态约束并
重新建立 V062 已有的外键、索引和保护触发器，不能只修改建表源文件。

V074 同时增加 `master_data_release_member_events`，以追加事件记录草稿发布批次
成员的加入、移除和替换。草稿批次可以移除失效成员，但不得删除这段关联历史。
已提交、已发布或已驳回批次的成员关系不可修改。

### 6.1 工价状态机

| 当前状态 | 目标状态 | 条件 |
|---|---|---|
| `draft` | `approved` | 独立批准已发布依赖，或成组发布待审批依赖 |
| `draft` | `voided` | 路线驳回，或工价制单人主动撤销 |
| `approved` | `retired` | 后续工价按有效期规则取代 |

`voided` 和 `retired` 是不可恢复、不可修改、不可删除的终态。已批准工价原有
不可变保护继续生效。

### 6.2 草稿唯一性

对于 `pending_approval` 路线，同一个
`route_version_id + process_version_id` 最多存在一个 `draft` 工价。服务层在
事务中校验，数据库触发器提供并发兜底。错误草稿必须先作废，再创建新草稿。

### 6.3 内容摘要

创建工价时保存路线版本和工序版本的内容摘要。批准或成组发布时重新计算并
比较；摘要变化返回冲突，不得静默接受。摘要用于防止相同版本 ID 在被驳回、
编辑、重新提交后错误复用旧工价。

## 7. 创建、审批和驳回流程

### 7.1 草稿路线

路线详情显示节点覆盖预览。参考价仅取上一条路线修订中相同 `process_id` 的
精确已批准工价；如果没有则显示空。参考价必须明确标注“仅供参考，不构成
当前版本覆盖”。所有正式定价按钮禁用，并提示“提交审批后可定价”。

### 7.2 待审批路线定价

路线进入 `pending_approval` 后：

1. 路线详情显示“为该版本定价”；
2. 工价页面的“待发布路线”视图显示相同精确节点；
3. 两个入口打开同一表单；
4. 路线和工序根及版本 ID 由系统锁定；
5. 用户填写正常工价、返工倍率、生效时间和备注；
6. 服务保存 `draft` 工价和两个内容摘要；
7. 响应返回 `approval_mode=grouped_release_only`。

### 7.3 已发布路线调价

当前已发布路线继续使用现有独立工价制单和独立批准流程。服务仍要求精确
路线版本和工序版本 ID，并沿用有效期不重叠与双人复核规则。

### 7.4 发布处置

路线每个节点在发布前必须选择：

- 使用与路线版本、工序版本完全匹配的工价版本；或
- 不适用计件工价，并由批准人填写原因。

工价制单人不能代替批准人确认“不适用”。待发布路线只要存在需要计件工价
的节点，就不能走路线独立批准，必须使用成组发布。

### 7.5 路线驳回

路线从 `pending_approval` 驳回到 `draft` 时，在一个事务中：

1. 校验路线 `row_version`；
2. 将该路线版本全部 `draft` 工价转为 `voided`；
3. 写入作废时间、操作者和路线驳回原因；
4. 写入每条 `price_version_voided` 事件；
5. 将路线版本转回 `draft`；
6. 写入路线驳回事件。

路线处于待审批发布批次时，禁止单独驳回，必须先驳回批次。批次驳回本身不
自动作废工价，因为驳回原因可能只是批次组织问题；随后只有在路线被驳回时
才作废其工价。

路线仍出现在草稿发布批次时可以被驳回，但该批次会因包含 `voided` 成员而
无法提交。批次制单人必须通过受控成员操作移除或替换失效路线及工价；系统
将原成员关系写入不可变成员事件后再更新活动成员集合。

## 8. API 契约

### 8.1 引用目录

```http
GET /api/route-price-versions/reference?include_pending=true
```

- 未提供 `include_pending` 时只返回当前已发布路线，兼容旧客户端；
- 新工价页面显式传入 `include_pending=true`；
- 新字段采用向后兼容的响应扩展；
- 需要 `wages:prepare` 或 `wages:approve`。

### 8.2 创建工价

```http
POST /api/route-price-versions
```

请求必须包含：

```text
route_id
route_version_id
process_id
process_version_id
expected_route_content_digest
expected_process_content_digest
normal_unit_price 或 normal_unit_price_micros
valid_from
idempotency_key
```

可选包含返工倍率和备注。服务基于规范化业务字段计算 `request_digest`。
两个 `expected_*_content_digest` 来自引用目录，用于检测选择后到保存前发生的
内容变化；服务只能保存从数据库重新读取的当前摘要。相同幂等键和相同请求
摘要返回原记录；相同幂等键和不同请求摘要返回冲突。

### 8.3 主动作废工价草稿

```http
POST /api/route-price-versions/<id>/void
```

请求包含 `row_version`、`reason` 和 `idempotency_key`。仅工价制单人可主动
作废自己创建的草稿；路线驳回产生的自动作废由路线服务在事务内执行。

### 8.4 草稿批次成员处理

```http
POST /api/master-data-release-batches/<id>/members/remove
POST /api/master-data-release-batches/<id>/members/replace
```

请求包含成员类型、精确版本 ID、批次 `row_version`、原因和幂等键。仅允许
修改 `draft` 批次。服务先写不可变成员事件，再更新活动成员集合；替换后重新
计算批次依赖摘要。

### 8.5 批次发布

批次创建应能从路线详情自动带入：

- 路线引用的待审批工序版本；
- 当前待审批路线版本；
- 该路线所有有效工价草稿。

批次提交和批准时都重新验证成员状态、精确绑定、摘要、工价处置和职责分离。

## 9. 权限和职责分离

| 权限 | 能力 |
|---|---|
| `route_versions:view` | 查看路线版本和工价覆盖 |
| `wages:prepare` | 查看定价目录、创建工价、作废自己的工价草稿 |
| `wages:approve` | 批准已发布路线的普通工价版本 |
| `master_data_releases:create` | 创建成组发布批次 |
| `master_data_releases:submit` | 提交成组发布批次 |
| `master_data_releases:approve` | 独立批准并原子发布批次 |
| `master_data_releases:reject` | 驳回待审批发布批次 |

发布批准人必须不同于批次制单人以及批次内各工序、路线和工价版本的制单人。
无 `wages:prepare` 权限的路线管理员只能查看覆盖状态。工资制单人可以在工价
页面定价，但不能修改或提交路线。

## 10. UI/UX 设计

### 10.1 工价版本页面

提供三个明确视图：

- 当前已发布；
- 待发布路线；
- 已作废记录。

路线和工序选项显示完整语义：

```text
机加工路线 A · 待发布 V2
第 3 道 · 精车 · 工序 V4
```

已发布版本和待发布版本即使名称、路线根和工序根相同，也必须作为独立选项。
待发布路线表单顶部固定显示：

> 本工价绑定待发布路线，不能单独批准，只能随路线成组发布。

待发布工价不显示独立批准按钮。

### 10.2 路线详情

“工价覆盖”使用可扫描表格：

```text
序号 | 工序及版本 | 当前状态 | 参考旧工价 | 精确新工价 | 操作
```

状态包括：

```text
待提交后定价
缺少工价
工价草稿
已批准覆盖
不适用计件
工价已作废
```

待审批路线提供逐节点“建立工价”和“批量建立缺失工价”。完成覆盖后提供
“创建成组发布批次”，自动预填依赖，用户仍需检查并提交。

### 10.3 深链接和选择稳定性

路线页进入工价页时使用 `route_version_id` 和可选 `process_version_id` 作为
查询参数。页面刷新后按精确版本恢复选择。所有 Vue `key`、分组和选择值均
使用精确版本组合，不使用根 ID。

## 11. 错误处理

服务返回稳定错误码和可操作说明：

| 错误码 | 含义 |
|---|---|
| `ROUTE_VERSION_NOT_PRICABLE` | 路线不是已发布或待审批状态 |
| `PROCESS_VERSION_NOT_FROZEN` | 路线节点引用可编辑工序草稿 |
| `PRICE_BINDING_MISMATCH` | 工价与路线节点版本不一致 |
| `PRICE_BINDING_STALE` | 路线或工序内容摘要已变化 |
| `PRICE_VERSION_VOIDED` | 工价已经作废 |
| `GROUP_RELEASE_REQUIRED` | 待发布路线工价不能独立批准 |
| `ACTIVE_RELEASE_BATCH_CONFLICT` | 路线仍在待审批发布批次中 |
| `STALE_ROW_VERSION` | 记录已被其他操作修改 |
| `IDEMPOTENCY_CONFLICT` | 幂等键被用于不同请求 |

前端根据错误码提供刷新、作废重建、驳回批次或进入成组发布的明确动作，不按
中文错误文本推断业务状态。

## 12. 兼容、迁移与发布

### 12.1 V074 预检

只读预检至少输出：

- 各工价状态数量和金额摘要；
- 空路线版本或工序版本绑定；
- 路线、工序根与版本归属错配；
- 同一待发布节点的重复草稿；
- 草稿工价关联的路线和工序状态；
- 草稿及待审批发布批次成员；
- 工价引用的工资事实和工资台账数量。

存在空绑定、错配或重复有效草稿时停止迁移并生成差异清单，不自动推断、删除
或覆盖业务数据。

### 12.2 数据迁移

- 已批准和已结束工价原样保留；
- 结构有效的既有草稿补齐内容摘要并写迁移审计事件；
- 迁移前后对账工价数量、金额、状态和精确绑定；
- 迁移重新建立并验证全部价格保护触发器；
- `PRAGMA foreign_key_check` 和 `PRAGMA integrity_check` 必须通过。

### 12.3 功能开关

新增：

```text
ROUTE_PRICE_PENDING_REFERENCE_ENABLED
ROUTE_PRICE_PENDING_WRITE_ENABLED
ROUTE_PRICE_PENDING_COMPAT_AUDIT_ENABLED
```

上线后先开启待发布引用查询和兼容审计，写入保持关闭。确认目录、版本绑定和
权限差异为零后，再单独批准开启待发布定价写入。已发布路线调价不受新开关
影响。

### 12.4 回退

生产部署前验证数据库、附件和前端发布备份。失败时恢复部署前数据库、代码和
前端文件，保留 `data/`、附件、预检报告和全部审计证据。生产部署、停服、迁移
和开关切换需要单独明确授权，不属于本设计确认的自动授权范围。

## 13. 测试矩阵

### 13.1 后端

- 默认引用只返回当前已发布路线；
- `include_pending=true` 增加待审批路线，不增加草稿或已驳回路线；
- 同一路线和工序的不同版本不合并；
- 创建请求和响应包含精确版本 ID、状态及摘要；
- 草稿路线不能创建工价，待审批路线可以创建草稿；
- 待审批路线工价不能独立批准；
- 工序草稿不能进入待审批路线；
- 路线、工序或摘要错配时拒绝创建或发布；
- 路线驳回事务性作废全部关联工价草稿；
- 已作废工价不可批准、恢复或加入可提交批次；
- 待审批批次成员路线不能单独驳回；
- 幂等重放返回同一结果，幂等冲突被拒绝；
- `row_version` 冲突不产生部分更新；
- 成组发布成功时工序、路线和工价同时生效；
- 任一步失败时所有状态、指针和事件回滚；
- 批准人与任一相关制单人相同时拒绝发布。

### 13.2 前端

- 正确显示三个工价视图；
- 选择项显示路线和工序版本号及状态；
- 多个修订版不因根 ID 相同而折叠；
- 创建请求包含四个精确 ID、两个预期内容摘要和幂等键；
- 草稿路线只预览，待发布工价不提供独立批准；
- 路线详情深链接正确预选路线和工序版本；
- 批量定价只为缺失节点生成草稿；
- 成组发布批次自动带入正确依赖；
- 驳回、作废、摘要过期和并发冲突提示准确；
- 桌面和移动宽度下表格、表单和操作区不重叠。

### 13.3 端到端

1. 创建路线 V2，绑定已发布或待审批工序版本；
2. 提交路线后从两个入口看到相同精确版本；
3. 为所有计件节点建立工价草稿；
4. 创建包含工序、路线和工价的发布批次；
5. 使用独立批准人原子发布；
6. 新订单解析到路线 V2 及对应工序和工价版本；
7. 历史订单继续使用原路线和原工价；
8. 创建路线 V3，定价后驳回，确认工价作废且不可复用。

## 14. 最终验收标准

- 数据库 `user_version=74`，完整性和外键检查通过；
- 已批准工价数量、金额和版本绑定与迁移前一致；
- 空绑定、归属错配和重复可用草稿均为零；
- 待发布路线计件节点的精确工价处置率达到 100% 后才能发布；
- 待发布引用兼容审计差异连续为零；
- 独立批准、原子回滚、幂等和并发测试全部通过；
- 新订单使用新版本，历史订单和工资台账保持原版本语义；
- 服务健康、数据库连接、审计事件和回退验证通过；
- 待发布定价写入开关只在完成上述验收后开启。
