# 日报表明细 CSV 精简设计

日期：2026-10-09

## 1. 目标与已确认范围

用户要求统计报表模块的日报表“导出明细”只保留员工、岗位、时间、订单号或序列号、产品编码和数量信息。数量信息已明确拆为正常数量、返修数量和报废数量。

采用直接精简现有 CSV 的方案，不新增简版/完整版切换，也不新增可配置导出列。用户已确认下述九列、逐记录导出、取消小计和截断保护规则。

只调整前端日报明细 CSV，不改变日报页面显示、导出汇总、PDF、后端统计计算、报工事实和数据查询口径。无需数据库迁移和附件迁移。设计文档单独保存在本地 Git；业务代码提交、推送、创建 PR、合并和生产部署仍另行确认。

## 2. 当前基线

- 基线提交：`3bc1c126f7d80317ea9f2b2d97102b414a2a026d`。
- 前端入口：`frontend/src/views/stats/DailyTab.vue` 的 `exportDetailCsv()`。
- 当前导出共 19 列，包含重复的“订单号/序列号”和员工小计行。
- `filteredEmployeeGroups` 已承载员工检索和正常/返修/报废类型筛选后的记录。
- `displayWorkNo()` 已实现序列件显示序列号、其他记录显示订单号。
- 公共 `exportCSV()` 已提供 UTF-8 BOM、CSV 字符转义及公式注入防护。
- API `/api/stats/daily` 已返回每条记录的类型、数量、时间及分组的员工岗位信息，并通过 `is_truncated` 提示数据截断。

## 3. 导出结构

固定九列，顺序不可交换：

| 列名 | 来源与规则 |
| --- | --- |
| 员工姓名 | 员工分组中的 `worker_name` |
| 工号 | 员工分组中的 `employee_no`；缺失留空 |
| 岗位 | 员工分组中的 `position_name`；缺失留空，不以工序名称替代 |
| 报工时间 | 每条记录的 `created_at`，保留完整日期及时分秒，不只导出时间部分 |
| 订单号/序列号 | 保留 `displayWorkNo()` 的现有规则；序列模式且存在序列号时取序列号，否则取订单号 |
| 产品编码 | 每条记录的 `product_code`；缺失留空，不以型号或产品名称替代 |
| 正常数量 | 正常报工填写该记录数量，其余类型填数值 `0` |
| 返修数量 | 返修报工填写该记录数量，其余类型填数值 `0` |
| 报废数量 | 报废报工填写该记录数量，其余类型填数值 `0` |

仅导出当前筛选的真实报工明细，每条记录一行。保留原分组及组内记录顺序，不跨记录合并，不重复写员工小计行。

删除班组、部门、客户、产品名称、型号规格、路线、工序、单独的类型/质检/备注以及重复编号列。正常、返修、报废通过三列数量表达，不额外增加“类型”列。

岗位使用当前 API 中的员工岗位名称，本次不建立或宣称历史岗位快照。数量保持记录原有精度，不为了显示而取整。

## 4. 导出路径与安全边界

`dailyStats()` → `dailyGroups` → 当前 `filteredEmployeeGroups` → 九列 CSV 数据 → 现有 `exportCSV()`。

保留原日期、产品、员工检索和报工类型筛选，保留导出权限和已有文件名格式。只有当前日报明细导出路径改变，公共 CSV 序列化组件及其他报表不变。

CSV 仍使用公共导出工具生成 UTF-8 BOM 和正确转义，姓名、工号、编号等含逗号、引号、换行或公式前缀的值仍受到现有防护。

## 5. 错误处理

- 无记录：不生成文件，沿用“没有数据可导出”的警告。
- `is_truncated` 为真：阻止明细导出，提示“数据已截断，请缩小筛选范围后再导出明细”；不得将已加载子集静默导出为完整明细。
- API 加载失败：沿用当前加载错误提示和处理，不新增绕过 API 的数据读取路径。
- 缺失岗位、工号或产品编码：留空，不猜测、不从其他字段套用。

本次不新增全量导出后端接口，不修改现有分页或每日统计边界。

## 6. 测试与验收

1. 表头严格等于九列，所有数据行均为九列，不存在重复列名。
2. 正常、返修、报废记录分别只有对应数量列非零，其他两列为数值 `0`；保留零数量和小数数量。
3. 每条筛选内报工恰好导出一次，不包含小计行；CSV 数量合计不因小计而重复。
4. 序列件导出序列号，订单模式导出订单号，序列号缺失沿用订单回退。
5. 完整时间保留日期及秒，缺失字段留空，岗位不会以工序名称代替。
6. 员工检索和类型筛选实际控制导出记录；无导出权限时保留现有按钮限制。
7. 无数据和截断状态不生成文件并显示明确警告。
8. 真实 CSV 下载验收列数、中文、BOM、特殊字符与公式前缀处理。
9. 回归确认导出汇总内容、日报页面和 PDF 保持不变。
10. 前端相关测试、生产构建、API facade 检查、导入环检查和 `git diff --check` 通过。
